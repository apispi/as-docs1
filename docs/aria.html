Aria AI Assistant

Aria is ApiSpi's AI assistant. This page starts with how to use Aria day-to-day, then goes deep on how it works — providers, modes, tool selection, and governance.

Using Aria

Open Aria from the dashboard sidebar (/dashboard/aria) and just type. Everything below makes your results better:

Pick a model and a mode

  • The model picker lists every model your connectors give you access to (see Available Models). Your choice is remembered across page loads.
  • The mode selector shapes how Aria answers: General for everyday work, Email when triaging your inbox, Research for deep, structured analysis (automatically uses a more capable model), Strategy for frameworks and decisions, Technical for precise answers with code.

Let Aria use your tools

Aria automatically has access to every tool from your active connectors — you don't invoke tools by name, you just ask for the outcome:

If you've connected…Try asking…
Gmail / Outlook"Summarise my unread email and draft a reply to the most urgent one."
Starter connectors (pre-connected)"Weather this weekend, top news, and the time in Singapore."
Your CRM (Salesforce, HubSpot…)"Which opportunities are closing this month?"
WhatsApp / Twilio"Text my plumber that I'll be home after 3pm."

Sources in replies are clickable — bare URLs are auto-linked.

Create things, not just answers

  • Documents — ask for a Word or Excel file ("Put that comparison in a spreadsheet"); a download link appears in the chat.
  • Images — with a Gemini connector active, ask Aria to generate images and graphics inline.
  • Uploads — attach a document and ask questions about it.

Talk instead of type

  • Use the mic button for voice input — recording stops automatically when you stop speaking. In workspace chat, ⌘⇧A / Ctrl+Shift+A toggles the mic.

Save and automate

  • Save prompts you'll reuse to My Prompts, then run any of them on a timer with My Schedule — results come back into this chat, badged scheduled.

Aria in Microsoft Teams

Organisations using Microsoft Entra SSO can chat with Aria natively in Microsoft Teams. The Teams bot maps your Teams identity to your ApiSpi account via Entra, and replies run on the same governed engine — your connectors, your governance, fully logged. Ask your admin about enabling the ApiSpi bot for your tenant.

Trust, but verify

  • Ask "What model are you using?", "What connectors do you have?", or "What mode are you in?" — Aria answers these directly and honestly, without going through the model.
  • If something is blocked, Aria tells you which restriction applied (mode, governance, or org policy) rather than failing silently.

Public Chatbot

Route: POST /chat — handled by ChatController.

Embedded on the public website to answer questions about ApiSpi's services, pricing, and partners.

Behaviour

  • Rate-limited to 30 messages per IP per minute.
  • Responses capped at 512 tokens.
  • Keeps up to 10 messages of conversation history per session.
  • Accepts up to 20 history entries — oldest are trimmed automatically.

AI Provider

Uses the Anthropic API (https://api.anthropic.com/v1/messages). Model is configured via services.anthropic.model (defaults to claude-sonnet-4-5). If no API key is configured, Aria returns a static fallback directing users to sales@apispi.com.

System Prompt Topics

Aria is primed with detailed knowledge of all 19 agents, the Digital Avatar service, training courses and pricing, the partner program, recent blog posts, and contact information.

Dashboard Aria

Route: POST /dashboard/aria/chat — handled by DashboardAriaChatController.

Authenticated users get a full-featured, personalised Aria with multi-provider support and live tool use.

Provider Resolution

Three AI providers are supported, resolved in priority order:

PriorityProviderCondition
1SCX AIUser has an active SCX connector and no explicit Anthropic/Gemini model requested.
2Google GeminiUser has an active Gemini connector and no Anthropic key or explicit Claude model.
3AnthropicDefault. Uses user's Anthropic connector key or the platform fallback key.

If no provider is configured, Aria falls back to keyword-matching static responses and shows a notice to connect a provider.

Beyond the three core providers, users can power Aria with any bring-your-own model-provider connector — Mistral, OpenAI, DeepSeek, Groq, Grok (xAI), Z.ai, Qwen, Moonshot (Kimi), AWS Bedrock, or a Local LLM. Picking a non-SCX provider routes the request through that connector directly (the dashboard no longer sends a literal model sentinel to SCX for these). Aria remembers the selected model and mode across page loads.

Model Selection

The resolved model follows this hierarchy per provider:

  1. Explicit model param in the request.
  2. Mode's configured model override (e.g. Research mode forces claude-opus-4-8).
  3. Model configured on the user's connector.
  4. Platform default (claude-sonnet-4-6 for Anthropic, gemini-2.5-flash for Gemini, default for SCX).

Personalisation & Grounding

Aria injects user profile data into the system prompt when available: preferred name, job title, industry, organisation, communication style, preferred response length, and custom instructions. The system prompt also grounds Aria in the user's local date/time and saved profile location, so "today", "this weekend", and weather/news questions resolve correctly (the Good Morning prompt uses the same localisation).

Disclosure Handling

Aria intercepts self-referential questions and answers directly — bypassing the LLM to ensure accuracy:

  • "What model are you?" → returns provider, model, and mode.
  • "What connectors do you have?" → lists the user's active connectors.
  • "What mode are you in?" → returns current mode.
  • "Tell me about your configuration" → full summary of all of the above.

Agentic Loop

Dashboard Aria runs a tool-use loop with up to 30 iterations per request (RunsAgentTools::MAX_TOOL_ITERATIONS). When the model returns a tool_use stop reason, Aria executes each tool call against the appropriate connector, appends the result as a tool_result block, and loops so the model can use the data — or call another tool — until it produces a final text response or the limit is reached. The same loop pattern runs for all three providers (runAgentLoop for Anthropic, runScxLoop for SCX, runGeminiLoop for Gemini).

Tool Selection

Aria does not pick the tool — the model does. The app's job is to curate which tools are even on the table; the model then chooses among them based on the user's message and each tool's description. There is no keyword routing or if/else dispatch in the codebase.

1. The app builds the candidate tool set

buildToolsWithMeta() assembles the list and filters it before the model ever sees it:

  • Built-in tools (e.g. generate Word/Excel) are always included.
  • Connector tools come from each of the user's active connectors' tool_definitions.
  • Filters applied, in order:
    1. Governance kill switch — if connectors_disabled is set (org policy or the user's own stricter override), no connector tools are included at all; only built-ins remain.
    2. Data-sovereignty — connectors whose country field matches a blocked country (org policy blocked_countries, merged with the user's own list) are dropped entirely (OrgPolicy::isCountryBlocked() / EffectiveGovernance::isCountryBlocked()).
    3. Per-connector disabled_tools — a user can disable individual tool names from a connector's tool_definitions without disconnecting the whole connector.
    4. Mode's allowedTools — e.g. Email mode restricts the candidate set to the Graph email tools only.

A connector tool is only a candidate if it survives every one of those gates.

2. Tools are handed to the model — choice is "auto"

The surviving tool list (each with name, description, input_schema) is sent in the API payload with no tool_choice set, which means the provider's default auto behaviour: the model decides whether to call a tool, and which one.

The tool description is the steering wheel. Connector authors write descriptions like "Always use this tool for current X news — do not answer from training data" to bias selection. The system prompt nudges further — it lists the user's active connectors/agents, the current mode's instruction, and the governance policy text.

3. The loop executes tool calls and feeds results back

On each iteration: call the model → if stop_reason !== 'tool_use', return its text answer (done) → otherwise, for each tool_use block, look up the connector by slug in CONNECTOR_TOOL_HANDLERS, run ->execute(), append the result, and loop. If the model calls a tool name that doesn't exist, the error result names the valid tools so the model can self-correct on the next iteration instead of failing the request.

What this means in practice

  • If two tools could plausibly match (e.g. two news connectors for "latest US news"), the model judges from their names/descriptions — it might pick one, or call several and synthesise the results.
  • To bias selection toward a tool, edit that tool's description or the mode/system prompt — not routing code.
  • To prevent a tool being chosen, remove it from the candidate set: disable the connector, block its country, disable that specific tool, or use a mode whose allowedTools excludes it.

Governance Layering

Each user has their own optional governance overrides (users.governance, a JSON column), editable on the Governance tab of /dashboard/profile (sub-tabs: Policy, Guardrails, Sovereignty, Limits — PUT /dashboard/profile/governance). EffectiveGovernance combines this with the global OrgPolicy at request time:

FieldHow the two layers combine
connectors_disabledKill switch — either layer disabling it disables it for that user.
daily_token_limitThe stricter (lowest) of the two limits that are set.
blocked_keywordsUnion of both lists (de-duplicated, case-insensitive).
blocked_countriesUnion of both lists — used for the data-sovereignty tool filter above.
contentBoth layers' free text are concatenated into the system prompt.

A user's own rules can only add to or tighten the org-wide policy — they can never loosen it.

Token Tracking

Input and output tokens are recorded per request in the token_usage table, attributed to the user, provider, and model. You can see your own usage on the Usage/Token tabs of /dashboard/profile.

For a shared, multi-user Aria conversation visible to a whole team, see Workspaces — it reuses the same connector/tool pipeline as Dashboard Aria but is not subject to the keyword guardrail or connector kill switch.

Built-in Tools

Built-in tools (in BuiltinTool) are always in the candidate set regardless of connectors:

  • Document generation — Word (.docx) and Excel (.xlsx) files, downloadable via GET /dashboard/aria/documents/{filename} (also serves .png/.jpg).
  • Image/graphic generation — available when the user has an active Gemini connector; images are generated with the user's own Gemini key and rendered inline in the chat.

Scheduled Runs in Aria

Results from My Schedule (/dashboard/schedule — saved Prompts run on a recurring schedule) surface directly in the Aria chat, badged as scheduled. The frontend polls POST /dashboard/aria/scheduled-results for pending results. Each schedule has its own detail page with a collapsible run history, and schedule times are anchored to the user's saved profile location's timezone (with "Next run" rendered in the schedule's own timezone).

Reply Rendering

Bare URLs in Aria replies are auto-linked, so sources (e.g. news links) are clickable.
