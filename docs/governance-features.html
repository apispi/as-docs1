Governance Features

The complete reference of ApiSpi's governance controls. Every feature here applies across all surfaces — Aria chat, scheduled runs, the LLM Gateway, MCP clients, and workspace chat — and every enforcement decision is logged and auditable.

How Governance Layers

Three layers combine at request time, strictest wins:

LayerSet byScope
Platform baselineApiSpiThe global floor every account inherits.
Organisation policyYour admin (see Organisation Setup)Everyone in your organisation.
Personal overridesYou, at /dashboard/profile → GovernanceYourself only — can tighten the layers above, never loosen them.

Kill switches OR together, limits take the lowest set value, keyword/country lists union, and free-text policy notes from every layer are all injected into the system prompt.

Content Controls

FeatureWhat it does
Policy notesFree-text rules (up to 50,000 characters) injected into every conversation — acceptable use, tone, disclaimers.
Blocked keywordsTerms that trigger the guardrail. Configurable action — block (reject), redact (mask), warn (proceed with warning) — and scope: user input, AI output, or both. Optional whole-word matching prevents false positives ("cat" won't match "category").
PII redactionAutomatically masks personal data (emails, card numbers, key-like strings) before it reaches a model.
Prompt-injection detectionTwo lines of defence: pattern matching for known attacks (DAN, role-play overrides, system-prompt extraction) plus an LLM-based moderation classifier as a second opinion.
Output moderationAI replies are scanned before being returned, with the same keyword/action machinery as input.
AI Firewall block modeThe pattern-based firewall (PII, injection, secrets) works per category in log or block mode. Existing rules stay log-only until an admin explicitly upgrades a category to block; an org can upgrade a category, never downgrade the platform baseline.
Policy-as-Code on passthroughGovernance rules are enforced even on raw gateway passthrough traffic — there is no ungoverned path to a provider.

Spend & Usage Controls

FeatureWhat it does
Token limitsDaily, weekly, and monthly per-user caps. On breach, requests get a fixed "limit reached" reply instead of a model call.
Spend capsDaily and monthly USD spend limits, independent of token counts.
Access windowsRestrict AI use to specific days and hours (e.g. Mon–Fri 9:00–17:00).
RetentionConfigurable retention period (days) for conversation data.

Model & Provider Controls

FeatureWhat it does
Allowed providersWhitelist which AI providers may answer at all.
Data sovereigntyBlock connectors by country — model providers carry country labels (DeepSeek, Qwen, Z.ai, Moonshot are labelled China), so one rule removes them everywhere.
Routing rulesSteer classes of requests to specific models/providers.
Connector kill switchIgnore everyone's saved AI connector config and fall back to the platform default provider — without touching user settings. Also strips every connector tool from the candidate set.

Tool & Action Controls

FeatureWhat it does
Tool access modesread_only drops all state-changing tools (send email, create files, post messages); approval requires explicit sign-off before actions execute.
Approval queueIn approval mode, pending actions wait for an approve/deny decision; a governed MCP call returns approval_required so external clients handle it gracefully too.
Blocked toolsBan specific tool names for everyone, regardless of other settings.
Per-connector rulesRules scoped to individual connectors; users can additionally disable individual tools on their own connections.
Autonomy budgetsmax_actions caps tool calls per run; action_time_budget force-stops long autonomous runs.
Per-API-key scopingEach gateway key can carry its own tool-access mode, a connector allowlist, and a daily USD spend cap — so an integration key can be far narrower than the user who owns it.
Emergency stopThe org-level kill switch halts all connector tool traffic on every surface at once. Idempotent; users are told an emergency stop is active instead of seeing cryptic errors.

Oversight & Assurance

FeatureWhat it does
Audit trailEvery guardrail event — keyword blocks, injection attempts, moderation flags — in one reviewable, filterable log.
Guardrail alertsIn-app and/or email notifications, for the affected user and for admins.
Policy versioning & rollbackPolicy changes are versioned; any previous version can be rolled back to in one step, and the last editor is recorded.
Dry-runTest a message against the current policy without sending it to a model — see exactly which rules would fire.
Posture view & exportA single summary of your effective governance posture, exportable for auditors and review boards.
Usage telemetryPer-user, per-model token consumption and per-tool connector activity logs — including which client (Claude Code, Cursor, n8n…) made each gateway request.
Real-time SIEM/webhook exportGovernance events stream to your SIEM (Splunk, Elastic, Sentinel/Defender) or any webhook endpoint — signed with a rotatable secret, with test delivery, per-delivery visibility, and automatic retries.
Governance digest emailsPer-organisation email digests summarising guardrail and usage activity.
Maker-checker approvalsOptional dual-admin control (off until a second admin exists): sensitive changes — policy edits, firewall rules, admin grants, widening an API key's scope or spend cap, retention changes — require a second administrator's approval.
Config-change auditAdministrative configuration changes are themselves audit events, alongside firewall block events.
Supply-chain validationExternal AI dependencies are pinned and re-verified, so an upstream change can't silently alter behaviour.

Where Enforcement Happens

  • Before the model sees anything — governance filters the candidate tool list (kill switch, sovereignty, blocked/disabled tools, mode restrictions), so a banned tool is never even visible to the model
  • On the way in — keyword guardrails, PII redaction, and injection detection run on user input
  • During the run — tool-access modes, approval gates, and autonomy budgets govern each tool call
  • On the way out — output moderation scans the reply before you see it
  • At the network edge — with the On-Prem Appliance, the same controls sit at a DMZ choke point with direct provider egress blocked at the perimeter
When something is blocked, ApiSpi tells you which restriction applied — a mode limit, your own setting, or org policy — instead of failing with a generic error. Supporting Essential Eight, ISM, and PSPF-aligned governance programs.
