LLM Gateway

Call your connected third-party services (connectors) programmatically — from your own code, scripts, or external tools — through a single authenticated endpoint. Your API key carries your identity and connector credentials, so you never manage upstream OAuth tokens or API keys yourself.

Base URL

https://apispi.com/api

The gateway is also available self-hosted as the On-Prem Appliance — same endpoints and controls, served from your own network with your appliance's hostname in place of apispi.com.

Authentication

All gateway requests are authenticated with a Bearer API key:

Authorization: Bearer gw_<your-key>

Keys are prefixed gw_ and 51 characters long. The raw key is shown once at creation — ApiSpi stores only a SHA-256 hash and cannot recover it. Keys do not expire by default; an explicit expiry can be set when a key is issued.

Issuing API Keys

There are two places to manage keys, both session-authenticated (the Bearer key itself is only used against the proxy/invoke endpoints below):

SurfaceRouteNotes
Dashboard UI (primary)/dashboard/profile#api-keysCreate, name, set an optional expires_at, revoke.
Self-service JSON APIGET / POST / DELETE /api/gateway/keysSame flow, scriptable. List returns id, name, key_prefix, last_used_at, expires_at, created_at — never the raw key.
 
POST /api/gateway/keys
Content-Type: application/json

{ "name": "my-script", "expires_at": "2027-01-01" }

Response (201) — copy key now, it is never shown again:

{
  "id": 12,
  "name": "my-script",
  "key": "gw_AbCdEfGhIjKlMnOpQrStUvWxYz0123456789012345678901",
  "key_prefix": "gw_AbCdEfGh"
}
curl 
curl -X POST https://apispi.com/api/gateway/keys \
  -H "Cookie: <your-session-cookie>" \
  -H "Content-Type: application/json" \
  -d '{ "name": "my-script", "expires_at": "2027-01-01" }'
Python 
import requests

resp = requests.post(
    "https://apispi.com/api/gateway/keys",
    json={"name": "my-script", "expires_at": "2027-01-01"},
    cookies={"apispi_session": "<your-session-cookie>"},
)
key = resp.json()["key"]
print(key)  # store this now — it is never returned again
JavaScript (fetch) 
const resp = await fetch("https://apispi.com/api/gateway/keys", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  credentials: "include", // sends your session cookie
  body: JSON.stringify({ name: "my-script", expires_at: "2027-01-01" }),
});
const { key } = await resp.json();
console.log(key); // store this now — it is never returned again
A key is not restricted to specific connectors — it inherits whichever connectors the owning user has actively connected. There is no per-key connector scoping or custom rate limit.

Proxy Endpoint

ANY /api/gateway/{connector_slug}/{path?}

Authenticates your key, resolves your active connector connection, runs the request through the AI firewall check, injects the upstream credential, and forwards the request.

  • {connector_slug} — a connector you have active (e.g. anthropic, microsoft, gmail)
  • {path} — the upstream API path (e.g. v1/messages, me/messages); optional for connectors with a single fixed endpoint
  • Any HTTP method; query params pass through on GET, JSON body on other methods
  • No rate limiting is currently applied to gateway/proxy requests

Example: call Anthropic through the gateway

The gateway injects your Anthropic API key automatically — you send only your ApiSpi gateway key.

curl 
curl -X POST https://apispi.com/api/gateway/anthropic/v1/messages \
  -H "Authorization: Bearer gw_<your-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-4-6",
    "max_tokens": 1024,
    "messages": [{"role": "user", "content": "Hello"}]
  }'
Python 
import requests

resp = requests.post(
    "https://apispi.com/api/gateway/anthropic/v1/messages",
    headers={"Authorization": "Bearer gw_<your-key>"},
    json={
        "model": "claude-sonnet-4-6",
        "max_tokens": 1024,
        "messages": [{"role": "user", "content": "Hello"}],
    },
)
print(resp.json())
JavaScript (fetch) 
const resp = await fetch("https://apispi.com/api/gateway/anthropic/v1/messages", {
  method: "POST",
  headers: {
    Authorization: "Bearer gw_<your-key>",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    model: "claude-sonnet-4-6",
    max_tokens: 1024,
    messages: [{ role: "user", content: "Hello" }],
  }),
});
console.log(await resp.json());
PHP 
<?php
$ch = curl_init("https://apispi.com/api/gateway/anthropic/v1/messages");
curl_setopt_array($ch, [
    CURLOPT_RETURNTRANSFER => true,

Example: list Microsoft 365 emails

The gateway injects a valid OAuth access token for Microsoft Graph, refreshing it if needed.

curl 
curl "https://apispi.com/api/gateway/microsoft/me/messages?\$top=10&\$select=subject,from,receivedDateTime" \
  -H "Authorization: Bearer gw_<your-key>"
Python 
import requests

resp = requests.get(
    "https://apispi.com/api/gateway/microsoft/me/messages",
    headers={"Authorization": "Bearer gw_<your-key>"},
    params={"$top": 10, "$select": "subject,from,receivedDateTime"},
)
for msg in resp.json()["value"]:
    print(msg["subject"])
JavaScript (fetch) 
const url = new URL("https://apispi.com/api/gateway/microsoft/me/messages");
url.searchParams.set("$top", "10");
url.searchParams.set("$select", "subject,from,receivedDateTime");

const resp = await fetch(url, {
  headers: { Authorization: "Bearer gw_<your-key>" },
});
const { value } = await resp.json();
console.log(value.map(m => m.subject));

Unified Gateway (Tool Discovery & Invoke)

Instead of constructing a raw HTTP request per upstream service, discover tools via a manifest and invoke them by name — the gateway resolves the owning connector and injects credentials automatically.

EndpointPurpose
GET /api/gateway/toolsManifest of every tool available to you, grouped by connector, with input JSON-schema.
POST /api/gateway/invokeInvoke a tool by name: { "tool": "tool_name", "input": { ... } }. Returns the result as JSON.

Discover tools

curl 
curl https://apispi.com/api/gateway/tools \
  -H "Authorization: Bearer gw_<your-key>"
Python 
import requests

resp = requests.get(
    "https://apispi.com/api/gateway/tools",
    headers={"Authorization": "Bearer gw_<your-key>"},
)
for tool in resp.json()["tools"]:
    print(tool["name"], "—", tool["description"])
JavaScript (fetch) 
const resp = await fetch("https://apispi.com/api/gateway/tools", {
  headers: { Authorization: "Bearer gw_<your-key>" },
});
const { tools } = await resp.json();
console.log(tools.map(t => t.name));

Invoke a tool

curl 
curl -X POST https://apispi.com/api/gateway/invoke \
  -H "Authorization: Bearer gw_<your-key>" \
  -H "Content-Type: application/json" \
  -d '{ "tool": "gmail_search_messages", "input": { "query": "from:someone subject:meeting" } }'
Python 
import requests

resp = requests.post(
    "https://apispi.com/api/gateway/invoke",
    headers={"Authorization": "Bearer gw_<your-key>"},
    json={
        "tool": "gmail_search_messages",
        "input": {"query": "from:someone subject:meeting"},
    },
)
print(resp.json())
JavaScript (fetch) 
const resp = await fetch("https://apispi.com/api/gateway/invoke", {
  method: "POST",
  headers: {
    Authorization: "Bearer gw_<your-key>",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    tool: "gmail_search_messages",
    input: { query: "from:someone subject:meeting" },
  }),
});
console.log(await resp.json());

OpenAI-Compatible Endpoints

GET   https://apispi.com/api/gateway/v1/models
POST  https://apispi.com/api/gateway/v1/chat/completions

Point any OpenAI-compatible client at https://apispi.com/api/gateway/v1 with your gateway key:

Python (openai SDK) 
from openai import OpenAI

client = OpenAI(base_url="https://apispi.com/api/gateway/v1", api_key="gw_xxxxx")
resp = client.chat.completions.create(
    model="claude-sonnet-4-6",
    messages=[{"role": "user", "content": "Search my connectors and summarize"}],
)
print(resp.choices[0].message.content)
JavaScript (openai SDK) 
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://apispi.com/api/gateway/v1",
  apiKey: "gw_xxxxx",
});
const resp = await client.chat.completions.create({
  model: "claude-sonnet-4-6",
  messages: [{ role: "user", content: "Search my connectors and summarize" }],
});
console.log(resp.choices[0].message.content);
curl 
curl https://apispi.com/api/gateway/v1/chat/completions \
  -H "Authorization: Bearer gw_xxxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-4-6",
    "messages": [{"role": "user", "content": "Search my connectors and summarize"}]
  }'

How it works: the request runs through the same agentic engine Aria uses (runAgentLoop) — your active connectors are auto-injected as tools and executed server-side — and the reply comes back in OpenAI's chat.completion shape, plus a non-standard apispi.tool_calls field showing which connector tools ran.

v1 limitations: non-streaming only (stream:true rejected) · model maps to Anthropic — non-claude-* models fall back to the platform default · client-supplied tools are ignored in favour of your connectors · max_tokens is fixed at 1024 · errors always render as JSON regardless of Accept header.

MCP Server & A2A

POST https://apispi.com/api/gateway/mcp
POST https://apispi.com/api/a2a

The gateway is also a Model Context Protocol (MCP) server — any MCP client (Claude Desktop/Code, other agents) can connect with a gw_ Bearer key or via a fully automatic OAuth flow (discovery documents, RFC 7591 dynamic registration, PKCE) — and an A2A server with a published agent card. ApiSpi can also consume remote MCP servers and A2A agents as connectors. See the dedicated MCP & A2A page for protocol details, authentication, client setup, and the wire-log debug facility.

Gateway Guardrails

Governance guardrails are enforced on every gateway path (proxy, invoke, OpenAI-compatible, MCP), not just Aria:

  • Blocked keywords — requests containing org/user-blocked terms are rejected.
  • Prompt-injection detection — pattern-based (PromptAttackDetector) plus an LLM-based moderation classifier (LlmSecurityClassifier) as a second line of defence.
  • Output scanning — responses are scanned before being returned.
  • Emergency stop — the org-level kill switch blocks all connector tool traffic when engaged.

ChatGPT Custom GPT

A public OpenAPI spec at https://apispi.com/openapi/gpt-actions.json ("ApiSpi Gateway Actions") lets you put your ApiSpi workspace inside ChatGPT as a Custom GPT with Actions. The GPT authenticates with a static gateway key (no OAuth needed) and uses two actions — listTools and invokeTool — mapping onto the unified gateway endpoints above. A step-by-step setup guide ships in the app repo at docs/chatgpt-custom-gpt.md.

How Upstream Auth Is Resolved

Connector typeHow it works
OAuth (Microsoft, Gmail, OneDrive)Gateway fetches the stored OAuth token, refreshes it if expired, injects as Authorization: Bearer <token>.
API key (Anthropic, Gemini, SCX AI)Gateway reads the connector's configured auth_header, auth_prefix, and auth_config_field and injects the key accordingly. Some connectors mark auth as optional.
Bring-your-own-backendIf the connector has no base_url, the gateway falls back to a user-supplied endpoint_url instead of returning 502.

Error Responses

All errors are JSON; upstream errors pass through with their original HTTP status code.

StatusMeaning
401 Missing API keyNo Authorization header supplied.
401 Invalid API keyKey not found (wrong value or revoked).
401 API key expiredKey has passed its expiry date.
403 ForbiddenNo active connection to the requested connector, or upstream credentials are missing.
404 Not foundConnector slug does not exist or is inactive.
502 Bad GatewayNo base_url configured and no user-supplied endpoint_url.

Usage Logging

Every proxy request is logged to connector_usage_log, success or failure:

  • user_id, connector_slug
  • tool_name — the upstream path/tool called
  • status (ok or error), result_count, error_message
  • created_at

No per-request HTTP status code, method, or response-time is recorded.

Key Security

  • Keys are hashed with SHA-256 before storage — the plain key cannot be retrieved
  • key_prefix identifies which key was used without exposing the full value
  • last_used_at updates on every request — use it to spot unused keys
  • Revoke immediately via the dashboard if a key is compromised
  • Use one key per integration so individual keys can be revoked independently
