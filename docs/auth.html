Authentication

ApiSpi supports three login methods: email/password, Google OAuth, and Microsoft Azure (Entra) SSO.

Login Methods

MethodRouteNotes
Email & passwordPOST /loginStandard Laravel session auth.
Google OAuthGET /auth/google/redirectCallback at /auth/google/callback.
Microsoft Azure SSOGET /auth/azure/redirectCallback at /auth/azure/callback.

Registration

Users self-register at /register or via Google/Azure OAuth. Email verification is not enforced by default.

Password Reset

  1. GET /forgot-password — request a reset link.
  2. POST /forgot-password — send the reset email.
  3. GET /reset-password/{token} — reset form.
  4. POST /reset-password — apply the new password.

Azure SSO & Role Mapping

When a user authenticates via Microsoft Entra, the platform fetches their group memberships and maps them to ApiSpi roles using config/azure.php.

'role_map' => [
    env('AZURE_ADMIN_GROUP', '') => 'admin',
    env('AZURE_AGENT_GROUP', '') => 'agent_user',
],

Groups are matched by display name or object ID. The AZURE_ADMIN_GROUP maps to the admin role and sets is_admin = true on the user.

If AZURE_SYNC_ADMIN=true, the admin flag is also removed when the user is no longer in the admin group. When false (default), admin can also be granted manually — Azure only adds the flag.

Roles & Permissions

RoleAccess
Regular userDashboard, subscribed agents, connectors, Aria, profile.
is_adminAll of the above + /admin/* panel.

The admin panel is protected by the admin middleware (IsAdmin) which redirects non-admins to the dashboard. The azure.role middleware (RequiresAzureRole) can gate routes by Entra group role and returns a 403 if the user lacks the required role.

User Personalisation

Authenticated users update their profile at /dashboard/profile. The personalisation JSON field on the user model is injected into Aria's system prompt to tailor responses:

  • Preferred name, job title, industry, organisation.
  • Communication style preference.
  • Preferred response length.
  • Custom instructions.
