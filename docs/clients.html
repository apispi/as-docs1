Compatible Clients

Installation guides for every terminal agent, IDE extension, workflow tool, and chat platform that works with the ApiSpi LLM Gateway. The gateway is OpenAI-compatible, so anything that lets you set a custom base URL and API key works — one ApiSpi key instead of per-provider credentials.

Connecting Any Client

Every guide below boils down to the same two settings:

SettingValue
Base URLhttps://apispi.com/api/gateway/v1
API keyYour gateway key (gw_…) — create one at /dashboard/profile#api-keys
Current v1 caveats (see API Gateway): responses are non-streaming (clients that hard-require streaming may not work yet), the model parameter maps to Anthropic models (claude-*; anything else falls back to the platform default), max_tokens is fixed at 1024, and the Responses API is not supported — use chat-completions mode wherever a client offers the choice. Model IDs are case-sensitive; take them from the Model Library.

Terminal Agents

Claude Code

No installation needed beyond Claude Code itself — it speaks the Anthropic wire format, so point it at the gateway's Anthropic proxy (your Anthropic key is injected server-side):

export ANTHROPIC_BASE_URL=https://apispi.com/api/gateway/anthropic
export ANTHROPIC_AUTH_TOKEN=gw_your_api_key_here
export ANTHROPIC_MODEL=claude-sonnet-4-6   # optional

claude

Alternatively (or additionally), connect over MCP so Claude Code can call your connected ApiSpi tools directly:

claude mcp add apispi --transport http https://apispi.com/api/gateway/mcp \
  --header "Authorization: Bearer gw_your_api_key_here"

Codex CLI

Log out of any existing session, then point the config at the gateway (~/.codex/config.toml):

codex logout
# ~/.codex/config.toml
model = "claude-sonnet-4-6"
openai_base_url = "https://apispi.com/api/gateway/v1"

Launch with codex; when prompted, choose Provide your own API key and paste your gw_ key.

Codex CLI prefers OpenAI's Responses API, which the ApiSpi gateway does not implement — if your Codex version cannot fall back to chat completions, use another terminal agent from this list.

Continue CLI

npm install -g @continuedev/cli
mkdir -p ~/.continue
# ~/.continue/config.yaml
name: apispi
version: 0.0.13
models:
  - name: claude-sonnet-4-6
    provider: openai          # the gateway is OpenAI-compatible
    model: claude-sonnet-4-6
    apiBase: https://apispi.com/api/gateway/v1
    apiKey: gw_your_api_key_here
cn --config ~/.continue/config.yaml

Hermes Agent

curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
source ~/.bashrc && hermes --version
hermes setup

In the wizard choose Custom OpenAI-compatible endpoint, enter base URL https://apispi.com/api/gateway/v1 and your gw_ key, pick a model, and choose a terminal backend. Settings land in ~/.hermes/config.yaml (keys in ~/.hermes/.env). hermes doctor diagnoses connection issues.

Kimi Code

# macOS/Linux
curl -fsSL https://code.kimi.com/kimi-code/install.sh | bash   # or: brew install kimi-code
# Windows (PowerShell)
irm https://code.kimi.com/kimi-code/install.ps1 | iex

Run kimi, type /provider, and configure a custom OpenAI-type provider — or edit ~/.kimi-code/config.toml directly:

[providers.apispi]
type = "openai"
api_key = "gw_your_api_key_here"
base_url = "https://apispi.com/api/gateway/v1"

Switch models mid-session with /model.

OpenCode

Run /providers (or /connect) inside opencode and add the gateway as a custom OpenAI-compatible provider, or configure it in ~/.config/opencode/config.json:

{
  "provider": {
    "apispi": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "ApiSpi Gateway",
      "options": { "baseURL": "https://apispi.com/api/gateway/v1" },
      "models": {
        "claude-sonnet-4-6": { "name": "Claude Sonnet 4.6" }
      }
    }
  }
}

Restart OpenCode after config changes. Also usable from VS Code/Cursor via the OpenCode extension ("Open opencode" in the command palette).

Pi

Configure the provider in ~/.pi/agent/models.json:

{
  "providers": {
    "apispi": {
      "baseUrl": "https://apispi.com/api/gateway/v1",
      "api": "openai-completions",
      "apiKey": "gw_your_api_key_here",
      "models": [
        { "id": "claude-sonnet-4-6", "name": "Claude Sonnet 4.6" }
      ]
    }
  }
}

To keep the key out of the file, set "apiKey": "APISPI_API_KEY" and export APISPI_API_KEY=gw_…. Run pi in your project and pick the model with /model.

Autohand Code

export OPENAI_BASE_URL=https://apispi.com/api/gateway/v1
export OPENAI_API_KEY=gw_your_api_key_here

autohand

With the environment set, all Autohand commands (multi-file editing, agentic search, autonomous generation) work as normal through the gateway.

IDEs & Editor Extensions

Cursor

  1. Cursor → Settings → Cursor Settings → Models
  2. Add OpenAI API Key → paste your gw_ key
  3. Enable Override OpenAI Base URL → https://apispi.com/api/gateway/v1
Only the AI panel (plan mode) and Agent-mode edits route through the gateway. Inline Edit (Cmd/Ctrl+K) and tab autocomplete stay on Cursor's own backend — use Claude Code, Cline, or Continue if you need every request governed.

Cline

  1. VS Code → Extensions → search Cline → Install
  2. Cline panel → gear icon → API Provider: OpenAI Compatible
  3. Base URL https://apispi.com/api/gateway/v1, API key gw_…, Model ID e.g. claude-sonnet-4-6

Verify with a request like "Create a hello world function in Python" — Cline should respond and offer to create the file.

Kilo Code

  1. VS Code (or any VS Code-based editor) → Extensions → search Kilo Code → Install
  2. Kilo Code sidebar icon → Settings → Providers
  3. Add an OpenAI-compatible provider with the gateway base URL and your gw_ key
  4. Pick the model from the picker at the bottom of the chat panel

VS Code (native) — coming soon

Native VS Code completion/chat integration is on the roadmap; use Cline, Kilo Code, or the OpenCode extension in the meantime.

Desktop Apps

OpenCode Desktop

  1. Download from opencode.ai/download (or brew install --cask opencode-desktop)
  2. Sidebar → Server → Providers → + Connect → add a custom OpenAI-compatible provider with the gateway base URL
  3. Paste your gw_ key and continue
  4. Pick a model from the chat input bar's model picker and start chatting — no config files needed

Workflow Automation

n8n

  1. n8n → Settings → Credentials → Add Credential → OpenAI
  2. API Key: your gw_ key · Base URL: https://apispi.com/api/gateway/v1 · Organization ID: leave blank
  3. Add an AI Agent node, connect a Chat Model edge, and select the credential
  4. Toggle off the Responses API on the model node — the gateway supports chat completions only

Run the workflow with a test prompt to verify.

Chat Platforms

OpenClaw

export APISPI_API_KEY=gw_your_api_key_here

Add the gateway as a custom provider in ~/.openclaw/openclaw.json:

{
  "models": {
    "mode": "merge",
    "providers": {
      "apispi": {
        "baseUrl": "https://apispi.com/api/gateway/v1",
        "apiKey": "${APISPI_API_KEY}",
        "api": "openai-completions",
        "models": [
          { "id": "claude-sonnet-4-6", "name": "Claude Sonnet 4.6",
            "contextWindow": 200000, "maxTokens": 8192 }
        ]
      }
    }
  },
  "agents": {
    "defaults": { "model": { "primary": "apispi/claude-sonnet-4-6" } }
  }
}

Reference models as apispi/<model-id>. OpenClaw then answers across Discord, WhatsApp, Telegram, and more — governed and logged by ApiSpi.

Beyond OpenAI-Compatible

Clients that speak richer protocols get more than chat completions:

  • MCP clients (Claude Desktop, Claude Code, claude.ai custom connectors) — connect to /api/gateway/mcp and call your connected ApiSpi tools directly. See MCP & A2A.
  • ChatGPT — a Custom GPT with Actions from /openapi/gpt-actions.json. See API Gateway.
  • A2A agents — task exchange via /api/a2a with discovery through the published agent card.
