On-Prem Appliance

The ApiSpi Appliance is the self-hosted deployment mode of the LLM Gateway: a governed AI gateway placed in your own network as the single enforced choke point for all LLM and agent traffic, with direct egress to AI providers blocked at the perimeter.

What the Appliance Provides

  • LLM gateway — OpenAI-compatible, so existing tools and compatible clients work unmodified
  • Policy, guardrails & governance — the same controls as the SaaS platform (see Governance How-To)
  • DLP / PII redaction on prompts and responses
  • Model routing & cost control across allow-listed providers
  • Full audit logging of prompts and responses, streamed to your SIEM

Recommended Network Placement

The appliance sits in its own DMZ / AI-services zone (a screened subnet) between the internal and perimeter firewalls:

Zones & Components

ZoneComponentsRole
Corporate network
(trusted)		 Employees & workstations (copilots, chat UI, browser plugins) · Business applications (CRM, ERP, service desk calling AI APIs) · Data centre / file servers · Identity provider (AD / Entra ID) · SIEM / SOC All AI consumers, the data sources agents read and act on (governed), and the control plane the appliance integrates with.
DMZ / AI services zone
(screened subnet)		 ApiSpi Appliance · Secure web proxy / WAF (existing egress controls, unchanged) The appliance is the single choke point for all AI traffic; it slots in beside your existing egress controls without replacing them.
Internet
(untrusted)		 LLM providers (Anthropic, OpenAI, Azure OpenAI, Google — allow-listed endpoints only) · SaaS connectors (M365, Salesforce, Slack — agent actions) · Remote / mobile users Only the appliance may reach provider endpoints; remote users come back in over VPN/ZTNA rather than around the controls.

Firewall Rules

FirewallRule
Internal firewallPermit only corporate subnets → appliance, on its gateway port. Nothing else crosses into the AI zone.
Perimeter firewallPermit only the appliance → allow-listed AI provider endpoints on TCP 443. Deny AI API destinations for everything else — direct egress to AI providers is blocked for all other hosts.

Together these rules make ApiSpi the single enforced choke point: no workstation, server, or application can talk to an LLM provider except through the governed gateway.

Why This Placement

  • DMZ / screened subnet, dual-firewall. The appliance sits in its own AI-services zone between the internal and perimeter firewalls, so both directions of AI traffic are explicitly permitted rather than implicitly possible.
  • Control-plane integration stays internal. The appliance authenticates users against your identity provider — SSO/RBAC decides who may use which models and agents — and streams full prompt/response audit logs to the SIEM, supporting Essential Eight, ISM and PSPF-aligned governance without exposing internal systems to the internet.
  • Remote users come back in, not around. VPN/ZTNA users reach the appliance the same way office users do, so policy, DLP and logging apply everywhere.
  • Cloud workloads follow the same rule. If you later add cloud workloads, point them at the same appliance (or a cloud-hosted replica) rather than letting them call providers directly.

Traffic Types

Getting the Appliance

The On-Prem Appliance is one of the two LLM Gateway deployment modes (alongside SaaS — see the Platform Overview). Register interest on the LLM Gateway page; the ApiSpi team will follow up on sizing, provider allow-lists, and identity/SIEM integration for your environment.
