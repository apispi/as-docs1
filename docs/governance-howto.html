Governance How-To

Practical guides for setting up and enforcing AI governance controls across your organisation.

Block Keywords

Prevent discussions on specific topics by adding blocked keywords to your org policy.

As an Admin

  1. Go to /admin/policy
  2. Scroll to the Guardrails section
  3. Add keywords to the blocked_keywords list (comma-separated)
  4. Choose the guardrail action: block (reject), redact (mask), or warn (proceed with warning)
  5. Set guardrail scope: input (user messages), output (AI replies), or both
  6. Click Save Policy

As a User

  1. Go to /dashboard/profile → Governance tab → Guardrails sub-tab
  2. Add your personal blocked keywords (these stack on top of org policy — you can only add, not remove)
  3. Your personal guardrail action applies to your overrides
Keywords are case-insensitive by default. Enable whole word matching to prevent partial matches (e.g., "cat" won't match "category").

Set Daily Token Limits

Cap how many tokens a user can consume per day to control costs.

As an Admin

  1. Go to /admin/policy
  2. In the Limits section, set daily_token_limit to your desired cap
  3. Save the policy

Users who hit the limit receive a fixed "limit reached" message instead of an AI response.

As a User

  1. Go to /dashboard/profile → Governance tab → Limits sub-tab
  2. Set a personal daily limit (must be lower than org limit — you cannot exceed it)

Enable the Connector Kill Switch

Instantly disable all user connector integrations and fall back to the platform's default AI provider.

As an Admin

  1. Go to /admin/policy
  2. Toggle connectors_disabled ON
  3. Save the policy

All connector tools are stripped from Aria's tool set immediately. No user data is affected — only the connectors are bypassed.

To re-enable, toggle connectors_disabled OFF. Individual users cannot override the kill switch.

Block Connectors by Country

Restrict connectors from specific countries for data sovereignty compliance.

As an Admin

  1. Go to /admin/policy
  2. In the Sovereignty section, add country codes to blocked_countries
  3. Save the policy

Connectors whose country field matches a blocked country are removed from Aria's candidate tool set before the model sees them.

As a User

  1. Go to /dashboard/profile → Governance tab → Sovereignty sub-tab
  2. Add additional country codes to your block list

Detect Prompt Injection Attacks

Enable injection detection to catch attempts to override Aria's instructions.

As an Admin

  1. Go to /admin/policy
  2. In the Guardrails section, toggle injection_detection ON
  3. Save the policy

Known prompt injection patterns (DAN attacks, role-play overrides, system prompt extraction) are blocked and logged. Users see a rejection message.

Receive Guardrail Alerts

Get notified when guardrails are triggered.

As a User

  1. Go to /dashboard/profile → Governance tab → Guardrails sub-tab
  2. Enable Guardrail alerts for in-app and/or email notifications

As an Admin

  1. Go to /admin/policy
  2. In the Guardrails section, enable Admin alerts
  3. Save the policy

Alerts are sent when any user triggers a guardrail (keyword match, injection attempt, output moderation flag).

Restrict Tool Access

Control what tools users can invoke through Aria.

Read-Only Mode

  1. Go to /admin/policy
  2. In the Tool Access section, set tool_access to read_only
  3. Save the policy

State-changing tools (send email, create files, post messages) are dropped from the tool set.

Approval Mode

  1. Set tool_access to approval
  2. Configure max_actions (max tool calls before pause) and action_time_budget (seconds before forced stop)

Tools that modify data require explicit user approval before execution.

Block Specific Tools

  1. Add tool names to the blocked_tools list in the admin policy
  2. These tools are removed from every user's candidate set regardless of other settings

Use the Emergency Stop

The org-level emergency stop halts all connector tool traffic at once — Aria, the gateway, MCP, everything.

  1. Go to /admin/policy
  2. Engage the Emergency stop control (its endpoint is the single writer of the flag, and the action is idempotent — engaging it twice is safe)

While engaged, a banner is shown across the admin shell, and affected users are told an org-level emergency stop is active (rather than seeing generic connector errors).

Set Access Windows

Restrict when Aria can be used (e.g., business hours only).

  1. Go to /admin/policy
  2. In the Limits section:
    • access_days — comma-separated days (e.g., 1,2,3,4,5 for Mon-Fri)
    • access_start — start time in 24h format (e.g., 09:00)
    • access_end — end time in 24h format (e.g., 17:00)
  3. Save the policy

Users attempting to use Aria outside the access window receive a "not available" message.

Review Guardrail Activity

Monitor what guardrails have been triggered.

As a User

View your own guardrail events at /dashboard/profile → Governance tab (shows recent blocks, injections, warnings).

As an Admin

Use the Audit tab on the Governance page (/admin/policy?tab=audit) for the governance audit trail, or query ActivityLog directly (filter by aria.guardrail.* or gateway.guardrail.* actions).

Editing Notes

  • Governance applies to every account — no plan gating on enforcement.
  • Policy free-text notes accept up to 50,000 characters.
  • Saving from a governance sub-tab keeps you on that sub-tab.
  • Guardrails (blocked keywords, injection detection, output scanning — including an LLM-based moderation classifier as a second line of defence) are enforced on all API gateway paths, not just Aria chat.
